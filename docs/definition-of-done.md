# NASH Definition of Done

A feature is considered complete only when all applicable items are satisfied.

## Product
- [ ] Acceptance criteria implemented
- [ ] Valid state transitions
- [ ] Empty state
- [ ] Error state
- [ ] Loading state

## Backend
- [ ] DTOs
- [ ] Validation
- [ ] Authorization
- [ ] Business rules
- [ ] Persistence
- [ ] Transaction where required
- [ ] Error contract
- [ ] Logging

## Frontend
- [ ] API integration
- [ ] Form validation
- [ ] Permission-aware UI
- [ ] Loading/error/empty states
- [ ] Responsive behavior
- [ ] Accessibility basics
- [ ] SEO if public

## Database
- [ ] Migration
- [ ] Foreign keys
- [ ] Unique constraints
- [ ] Required indexes
- [ ] No accidental destructive changes

## Testing
- [ ] Unit tests
- [ ] Integration tests where relevant
- [ ] E2E test for critical workflow where relevant

## Quality
- [ ] Lint passes
- [ ] Typecheck/build passes
- [ ] Backend tests pass
- [ ] Frontend tests pass where configured

## Documentation
- [ ] API docs updated
- [ ] Domain docs updated
- [ ] Architecture/ADR updated if decision changed
